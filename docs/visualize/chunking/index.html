Stage 1 · Chunking

Chunking, Visualized in 3D

Watch one of the course lessons go through the exact splitter this repo uses: RecursiveCharacterTextSplitter with 1,000-character chunks and 200 characters of overlap.

Real data: the lesson text and every split point come from running the pipeline's splitter at build time.

3D needs WebGL, which this browser doesn't support. The steps below describe each stage of the animation.

Drag to orbit · scroll to zoom · hover to read

  1. One document

    A lesson file loaded from data/raw/. Too long to embed or retrieve as one unit, so it has to be split.

  2. Look for natural breaks

    The splitter tries separators in order: blank lines (paragraphs) first, then single newlines, then spaces. Grey lines mark the paragraph breaks it prefers to cut at.

  3. Cut at about 1,000 characters

    Scanning down the text, it closes a chunk at the last good break before 1,000 characters. The cyan lines are the real cut points for this lesson.

  4. Chunks separate

    Each piece becomes its own chunk. Hover a chunk to see its exact size and where it sits in the original text.

  5. Overlap carries context

    The amber bands are text repeated between neighbouring chunks, so a sentence near a cut is still whole in at least one chunk. The default overlap is up to 200 characters.

  6. Characters are not tokens

    chunk_size counts characters, not tokens. In English, 1,000 characters is roughly 250 tokens, which is what models and costs actually measure.

  7. Stamped with metadata

    Every chunk carries its source filename. Without it, the final answer couldn't cite where a fact came from. Next: turning each chunk into numbers.

Where this happens in the code

  • src/pipeline/ingest.py: chunk() splits each document and copies its metadata to every chunk
