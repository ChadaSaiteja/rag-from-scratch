Sentence to Vector Playground

Type a question and follow it through every transformation a RAG system applies before it can search: tokens, IDs, a vector, a position in space, and the closest chunks.

Try:

No AI model runs here. This is a keyword representation (TF-IDF over the 585-word vocabulary of this repo's 21 chunks), computed in your browser with the same math as the other visualizations. It shows the shape of each step; real embedding models capture meaning, not just shared words.

  1. 1

    Your sentence

    Exactly what a user would type as a question.

  2. 2

    Split into tokens

    The text is lowercased and split into pieces. Very common words like how and the carry little meaning, so this representation drops them. Real LLM tokenizers go further and split rare words into sub-word pieces such as retriev + al.

  3. 3

    Look up token IDs

    Every remaining word is replaced by its position in the vocabulary, a fixed list of known words. Words the vocabulary has never seen can't be represented.

  4. 4

    Build the vector

    The sentence becomes one list of numbers, one slot per vocabulary word. Each lit cell is a word from your sentence; brighter means rarer in the corpus, so more distinctive (TF-IDF weighting). Real embedding models instead produce a few hundred to a few thousand dense numbers where every slot is used.

  5. 5

    Place it in space

    The long vector is projected down to 3 dimensions so it can be drawn next to the 21 stored chunks. Drag to orbit, hover a point to read its chunk.

    3D needs WebGL, which this browser does not support. The position is listed below.

  6. 6

    Find the nearest chunks

    Similarity is the cosine between your vector and each chunk's vector. These top matches are what retrieval would hand to the LLM.
