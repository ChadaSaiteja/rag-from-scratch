Hybrid Retrieval, Visualized in 3D

Pick one of the pipeline's evaluation questions and watch hybrid search work: two retrievers each pick their top 3, and Reciprocal Rank Fusion merges them into one ranked list.

Real rankings from the real chunks, using BM25 and weighted Reciprocal Rank Fusion (50/50, c=60) as in the pipeline. The vector side uses the same TF-IDF stand-in as the previous page, and a single query: the real pipeline also asks Gemini for 3 rephrasings.

3D needs WebGL, which this browser doesn't support. The steps below describe each stage of the animation.

Drag to orbit · scroll to zoom · hover to read

  1. The stored space

    All 21 stored chunks, waiting. Choose a question above to change the search.

  2. The question becomes a point

    The question is embedded with the same model as the chunks, so it lands in the same space.

  3. Vector search

    The three chunks most similar to the question by cosine similarity. Good at matching meaning.

  4. Keyword search (BM25)

    BM25 scores exact shared words, weighting rare words more. Good at names, codes and precise terms that vectors can blur.

  5. Reciprocal Rank Fusion

    Each retriever's ranking is converted to a score of 0.5/(60 + rank) and the scores are added. Chunks both retrievers like rise to the top, and the two scoring scales never need comparing.

  6. Handed to the prompt

    The fused chunks go into the prompt, each tagged with its source filename so the answer can cite it. The panel shows whether the expected file was retrieved.

Where this happens in the code

  • src/pipeline/hybrid_search.py: BM25Retriever + vector retriever fused by EnsembleRetriever
  • src/pipeline/evaluation.py: the five questions and their expected source files
